# Builder rules

You are the builder on this project. A reviewer reads your status report and
your actual diff after every task.

## Before you start

- Work only on the one task file you were given.
- Run `git status`. If the tree is not clean, stop and say so.
- Move the task file from `docs/handoffs/todo/` to `docs/handoffs/doing/`
  with `git mv`.
- Read `README.md`, `docs/ARCHITECTURE.md` and every file listed under the
  task's "Context" before writing code.

## While building

- Build step by step and run each part before moving on.
- Readable code with docstrings. No over-engineering, no features the task does
  not ask for.
- Cross-platform: Windows, Linux and macOS. Use `pathlib`. No Windows-only
  paths, modules or APIs unless there is a fallback for the other two.
- Core audio classes in `engine/` never print and never prompt. They return
  values or raise exceptions. Only `cli/` (and later the server) talks to the
  user.
- Nothing slow inside an audio callback: no file I/O, no printing, no waiting
  on a lock, no sleeping.
- Do not add a dependency the task does not name. If you need one, write it as
  an open question.
- Run commands from the repo root.

## Never

- Never delete, move or overwrite user recordings or projects. The only
  exception is a take the user explicitly chose to delete or redo in the CLI.
- Never commit audio files or local config. Do not edit `.gitignore` to get
  around it and do not use `git add -f`.
- **No AI attribution anywhere**: no `Co-Authored-By` lines, no "generated by"
  notes in commits, pull requests, comments or file headers.
- Never change a decision recorded in `docs/ARCHITECTURE.md`. If you disagree,
  write it as an open question in the status report.
- Never touch files listed under the task's "Out of scope / don't touch".
- Never push. The reviewer and the user decide when to push.

## Finishing

- Run every "Done when" check and paste the **real** output into the status
  report. If a check fails, say so. Do not claim the task is done.
- Write `docs/handoffs/done/NNN_slug_status.md` with these sections: files
  changed, commands run, check outputs, open questions, skipped items.
- Move the task file from `doing/` to `done/`.
- Commit everything with the message `task NNN: <title>`.

## If blocked

If you are blocked or the task is unclear: stop, write the question in the
status report, and commit what you have. Do not improvise big changes.
